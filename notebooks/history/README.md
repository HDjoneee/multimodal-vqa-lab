# 历史 Notebook 存档

三个阶段的数据规模各留一份 notebook，用于对照和写报告时回溯。当前在用的版本放在上一级 `notebooks/`。

| 文件 | 阶段 | 训练 | 评估集 | 关键结果（Exact Match） |
| --- | --- | --- | --- | --- |
| `v1_pilot_3200qa.ipynb` | 四题型 pilot | 3,200 QA / 3,087 图 | dev 320 / test 320 | test: 仅文本 29.1%，图文融合 43.4%，微调 43.4% |
| `v2_top1000_12400qa.ipynb` | Top-1,000 单模型 | 12,400 QA / 2,000 图 | dev 4,960 词表内 | dev: 仅文本 34.0%，图文融合 39.1% |
| `v2_three_way_12400qa.ipynb` | 三组对齐 | 12,400 QA / 2,000 图 | dev 4,960 词表内 | 34.5 / 38.8 / 37.9 |
| `v3_top1000_20989qa.ipynb` | Top-1,000 单模型 | 20,989 QA / 2,000 图 | dev 8,083 词表内 | dev: 仅文本 36.8%，图文融合 42.6% |
| `v3_three_way_20989qa.ipynb` | 三组对齐 | 20,989 QA / 2,000 图 | dev 8,083 词表内 | 35.9 / 41.6 / 40.8 |

## 三个阶段的差别

**v1** 是规模最小的一版：四类问题各抽 800 题，答案词表按类型分别建（2 / 11 / 12 / 10 类），总共只有 35 类。它把微调与冻结的差异放大到最明显，但题型被人为均衡，不能当作完整 VQA v2 的成绩。

**v2** 换成 Top-1,000 闭集分类，词表来自官方全量训练集的答案频次。抽样受"每图恰好 6 或 7 题"的配额限制，2,000 张图固定产出 12,400 条 QA。这一版的副作用是词表里有 171 个类从未出现，开发集有 81 道题的答案类别训练时没见过。

**v3** 去掉 6/7 题限制，改成在所有 ≥6 题的图上按密度分层等比例抽样。训练集涨到 20,989 条，词表死类降到 100，开发集未见类题降到 60 道。评估集同时扩到 8,083 条。

## 两版 notebook 的呈现方式不同

`v1` 与 `v2_top1000` 是实际执行过的 notebook，每个代码单元下挂的是当时的 stdout。`v2_three_way` 与两个 `v3` 是先用 `scripts/build_notebook.py` 生成结构、再把 `results/` 里的曲线内嵌、最后把完整运行日志作为末尾单元附上。这样改评分口径后不必为了美观重跑训练。

重新生成带图与日志的 notebook：

```powershell
python scripts/build_notebook.py --source scripts/three_way_experiment_source.py --output notebooks/VQA_ThreeWay.ipynb --attach-log results/three_way_run.log
```

## 一个不要混用的地方

v1 的 43.4% 与 v3 的 41.6% 不能直接比较。前者是 320 题测试集上的 35 类分类，后者是 8,083 题上的 1,000 类分类，难度、题型分布、随机波动全部不同。跨版本只能比同一指标的方向，不能比绝对数值。
